# Art Guide：来源与生产治理

## 目标

建立原创、可读、适合移动端和 PC 的 2D 像素视觉，同时让所有资源具备清晰来源。

正式尺寸、调色板、光照、动画、分层和画质档位以 `docs/ART_BIBLE.md` 为准；具体生产范围以 `docs/ART_ASSET_LIST.md` 为准。

## 已确认的视觉方向

- 东方幻想故乡：山雾、木构、石径、农田、药草与魔法遗迹。
- 轮廓清晰，角色、可交互地块和背景有明确层级。
- 使用有限色板和统一光照方向。
- 表层日常温暖、通透、令人愿意长期停留；渗漏与真相线逐步转向冷暗、失真和压迫。
- 不模仿或描摹任何具体商业游戏的角色比例、建筑、UI、地图或图块。

## MVP 资源策略

- 玩法验证阶段优先使用原创几何占位图和简单色块。
- 没有来源记录的图片、字体、音频不得导入项目。
- AI 生成资源若使用，必须记录生成工具、日期、提示词摘要、人工修改和适用条款，并进行相似性审查。
- 购买或开源资源必须保留许可证、购买凭证和作者信息。
- 项目运行时素材的逐项来源记录维护在 `docs/ASSET_SOURCES.md`。

## Demo 资源策略

技术占位资源不会一次性全部替换。正式美术按以下顺序生产：

1. 阶段 10B～10D 先完成三地图拓扑、NPC/玩家外观简报，以及同一地点“表层日常/第一处异常”的文字和构图目标；这一步是设计简报，不是批量游戏资源。
2. 阶段 11 先搭建三张地图灰盒，再用一个玩家、草地/泥土、小屋、树和雾叶草组成五类运行时视觉验证包。
3. 在 Cocos 中验证 32×32 瓦片、角色比例、色板、光照/叠层、过滤、动画和移动端可读性，并用最小异常覆盖层证明基础资源可以复用。
4. 五类资源通过且阶段 10C 已选定角色后，制作一名核心角色的立绘试制包；微信内存烟测通过前不批量生产高分辨率立绘。
5. 锁定资源规格后，再按内容层级制作三张正式地图、玩家动画、NPC、两种作物、物品图标和主要 UI。
6. 每批资源进入项目时同步更新 `ASSET_SOURCES.md`，并在 640×360、另一横屏比例和目标平台检查。

Demo 的最低正式资源清单与验收标准见 `docs/DEMO_SCOPE.md`。未通过双状态目标视觉样片评审前，不批量生产整套地图、NPC 或角色动画。

## 双状态视觉护栏

- 日常状态不能因为隐藏真相线而从一开始就显得明显恐怖；玩家应相信这里可以成为舒适的长期生活空间。
- 第一次异常优先改变雾、光照、环境色、远景轮廓、UI 微动和声音，不立刻替换所有地表与建筑。
- 阴暗状态仍要保持交互物、角色脚点、碰撞物和文字清晰，不能用低亮度掩盖可读性问题。
- NPC 的异常表现优先通过短暂帧错、朝向、停顿、色偏或影子表达，避免无差别血腥化。
- 任何 AI 生成概念图都只能作为原创方向探索，进入游戏前必须人工重绘、记录来源并完成相似性审查。

## Pixel Rules

- 基础瓦片为 32×32 像素。
- 逻辑设计分辨率为横屏 640×360。
- 第一版角色单帧统一为 96×96；128×128 只作为未来整体升级备选。
- 角色脚点使用底部中心基准，碰撞体仍由玩法配置决定。
- 像素资源使用 Point/Nearest，避免非整数缩放和有意模糊。
- 正文使用清晰中文屏显字体，标题才优先考虑像素字体。
- 图集 padding、extrude 与压缩参数在首个 Cocos 视觉样片验证后锁定，未验证前不批量打包。

必须在目标分辨率检查：

- 非整数缩放导致的抖动和模糊。
- TMX 图块接缝与纹理渗色。
- 相机移动时的像素稳定性。
- 手机安全区和触控按钮可读性。

Cocos 3.8.5 及之后的 TiledMap 图集边缘处理有特别说明，地图阶段按所选编辑器版本复核：<https://docs.cocos.com/creator/3.8/manual/en/asset/tiledmap.html>

## Naming and Layout

运行时导出目录：

```text
assets/art/
  characters/
  environment/
  crops/
  items/
  ui/
  effects/
  lighting/
assets/animations/
assets/materials/
assets/shaders/
```

- 文件名使用小写英文 `snake_case`。
- 完整命名和 Sprite Sheet 行列顺序见 `docs/ART_BIBLE.md`。
- 可编辑源文件统一放在仓库根目录 `art-source/`，不与 `assets/art` 导出文件混放。
- `art-source/exports` 是待审核区，只有审核通过的文件才能复制到运行时目录。

## UI

- 先满足触控点击面积、对比度和安全区，再装饰。
- 微信端和 PC 端共享信息架构，可有不同输入提示。
- 图标源画布推荐 64×64；默认快捷栏/背包格以 48×48 逻辑像素为基准，触控热区建议不小于 56×56。
- 小字号中文正文不强制像素化。
- 不复制其他游戏的工具栏布局、图标造型或像素字体。

## Quality Profiles

- `wechat-low` 与 `pc-high` 共享玩法、稳定资源 ID 和首版 96×96 角色资产。
- 昼夜覆盖、假阴影、局部柔光、粒子、草木动态、水面和简单 Shader 都有独立开关。
- 微信默认限制屏幕内粒子和局部柔光数量，并关闭高成本后处理。
- PC 可以提高预算或启用共享简单 Shader，但第一版同样不使用景深、体积雾、实时阴影和高成本 Bloom。
- 关闭表现效果不得改变天气、时间、异常事件、碰撞或交互结果。

## Audio

- 技术 MVP 可完全无音乐；Demo 至少需要原创或授权的日常环境层、关键动作反馈和第一处异常的声音变化。
- 音频必须支持静音和前后台暂停。
- 不使用任何商业游戏解包或重新录制的音频。

## Review Checklist

- 来源、作者、许可证和修改记录齐全。
- 与参考商业作品没有近似角色、建筑、图块、UI 或图标。
- 导入设置与像素规范一致。
- 同一小场景的白天、黄昏、夜晚和下雨状态均通过检查。
- `wechat-low` 全部增强可关闭，`pc-high` 不引入玩法分叉。
- 在微信真机与 Steam Windows 构建上检查清晰度、内存和加载。
