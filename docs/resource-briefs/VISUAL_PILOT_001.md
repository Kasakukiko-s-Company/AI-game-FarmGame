# `VISUAL-PILOT-001`：首轮视觉语言与角色一致性试制

## 新对话标题

《雾乡如昨》资源任务：首轮视觉语言与角色一致性试制

## 可直接复制的任务说明

```text
我要为 Cocos Creator 游戏《雾乡如昨》启动独立美术资源任务 VISUAL-PILOT-001。

本任务只负责视觉探索、候选比较和小型试制，不修改主线玩法代码、JSON、PLANS.md、Cocos 场景、.meta、现有存档或 assets/ 运行时目录。

一、项目方向

游戏是架空魔法世界中的田园生活模拟。表层温暖、安静、适合长期生活；隐藏剧情带有悬疑与微恐，但第一批画面不能从一开始就显得明显恐怖。

正式方向：HD 像素增强版游戏场景 + 精美 2D 人物对话立绘 + 轻量光照和粒子氛围 + 少量共享 Shader。

不采用完整 3D HD-2D，不复制《星露谷物语》《八方旅人》或其他商业游戏的具体角色、地图、UI、建筑、配色和特效。

目标平台：微信小游戏 + Windows/Steam。
逻辑分辨率：横屏 640×360。
基础 Tile：32×32。
场景角色单帧：96×96，约 3～4 头身。
对话立绘审核尺寸：512×768 或同比例；未来正式立绘源文件建议使用 1024×1536 分层制作。
统一左上主光，关闭粒子和 Shader 后仍需清楚可读。

二、本批目标

建立能够指导后续玩家、NPC、地图和 UI 的统一视觉语言，并验证：

1. 32×32 地图 Tile 的表现密度；
2. 96×96 场景角色的比例和轮廓；
3. 场景 Sprite 与精美人物立绘的一致性；
4. 温暖日常与轻微异常复用同一套基础资产的可行性；
5. 手机屏幕缩小后的角色、地块和互动信息可读性。

三、本批角色

只处理两名角色：

1. 男性主角
   - 魔法学院新生；学院无限期封校后回到故乡；
   - 外表保留少量学院背景，但适合农务生活；
   - 发型、服装主色和一个代表性配饰必须清楚。

2. 沈禾 npc_shen_he
   - 当前 Demo 的核心 NPC 和首个关系/对白垂直切片角色；
   - 同时考虑场景像素 Sprite 与对话立绘；
   - 本批只探索 neutral、smile、surprised，不制作完整八表情和大量姿势。

两者的年龄感、体型、发型、服装、配饰和配色必须在场景 Sprite 与立绘之间一致。

四、小场景内容

只制作一个风格验证小场景：

- 一小块草地和泥土；
- 一栋故乡小屋；
- 一棵树；
- 雾叶草三个成长阶段；
- 男性主角与沈禾；
- 白天基础状态；
- 一张轻微异常对照效果稿。

暂不制作完整村庄、四张完整地图、十五名 NPC、完整家具库、矿洞、敌人、战斗动画、完整 UI 或正式原声带。

五、AI 候选和用户确认规则

所有依赖 AI 随机生成的关键视觉选择，每个评审批次至少提供 5 张独立候选，默认提供 6 张，编号 A～F。

A～F 始终是六个独立候选。可以为了说明方便归纳为三组视觉语言，但归组不能替代六张独立原图，也不能自动把同组候选合并。

第一轮：整体视觉方向

1. 生成至少 6 张可以单独查看的完整候选图，并额外提供一张 A～F 总览图。
2. 六张尽量使用相同场景内容、角色数量、镜头角度和画面比例，便于横向比较。
3. 候选必须在像素密度、人物比例、轮廓、建筑/植物语言、色板、光照和东方幻想表达上真正不同；不能只换颜色、天气或随机小细节。
4. 每张说明设计重点、优点、风险、转换成 32×32 Tile/96×96 Sprite 的难度，以及微信端可读性和性能风险。
5. 等待用户明确选出两个入围方向，不得自动替用户定稿。

AI 可以提供推荐及理由，但推荐不构成入围、淘汰或确认。
只有用户明确回复候选编号并使用“入围”或“确认”等明确语义后，才能更新确认状态。

第二轮：入围方向优化

1. 两个入围方向分别生成至少 3 张优化变体，共至少 6 张独立图。
2. 保持相同角色、内容和基本构图，重点解决第一轮评审问题。
3. 对比主角/沈禾一致性、Sprite/立绘一致性、温暖日常和轻微异常复用能力。
4. 等待用户明确选择一个正式视觉方向。

第三轮：角色候选

1. 正式方向确认后，男性主角至少提供 5 套造型候选。
2. 沈禾至少提供 5 套造型候选。
3. 每套展示正面、侧面或三分之二视角、服装配色、代表配饰、场景像素比例示意和立绘风格示意。
4. 不能只改变发色或衣服颜色作为不同方案。
5. 用户分别确认两名角色后，才能完善比例稿和表情试制。

正面、背面和侧面的完整比例稿属于本轮角色阶段，不属于第一轮整体视觉方向探索的必交付物。

第四轮：表情试制

1. 沈禾 neutral、smile、surprised 各自在首次探索时提供至少 5 个强度或细节候选。
2. 表情语言确认后，后续同类状态可以按规范制作，不要求每次重新生成五张。
3. 未经用户确认，不得把不同候选的五官、服装和姿势自动拼接成最终角色。

六、制作工具路线

- Codex 图像生成、即梦或其他生成工具用于概念方向、人物造型和场景构图；
- AI 输出只是候选，不是精确像素成品；
- 方向确认后使用 Aseprite、Krita 或其他工具整理无缝 Tile、96×96 Sprite、透明边缘、动画脚点和分层立绘；
- 不让生成工具直接交付未经检查的最终 Sprite Sheet。

七、交付物

第一轮：至少 6 张独立方向图、1 张总览图、逐张说明。
第二轮：两个入围方向各至少 3 张优化变体、对比总览。
角色阶段：主角至少 5 套、沈禾至少 5 套、用户确认后的角色设定页。
表情阶段：沈禾三个试制表情各至少 5 个首次候选。

所有阶段同时交付：

- 独立原图与总览图；
- 候选稳定编号；
- 提示词摘要、工具、模型/版本、日期、参考图、关键参数和可用 seed；
- 如果生成工具没有暴露精确模型版本或 seed，分别记录为 `not_exposed` 或 `unavailable`，不得自行推测或伪造；
- 人工修改说明；
- 商业使用条件与第三方素材来源；
- 淘汰稿、入围稿和最终确认记录；
- 尚需人工像素整理的内容；
- HANDOFF.md。

八、输出位置

概念与审核稿：art-source/concepts/visual-pilot-001/
AI 原始输出：art-source/ai-generated/visual-pilot-001/
Aseprite 或分层源文件：art-source/aseprite/visual-pilot-001/
审核导出：art-source/exports/visual-pilot-001/
交接记录：art-source/concepts/visual-pilot-001/HANDOFF.md
确认记录：art-source/concepts/visual-pilot-001/CONFIRMATION_LOG.md

art-source/exports/visual-pilot-001/ 仅用于方向确认后的审核导出；第一轮概念候选不要求创建运行时或审核成品。

当前不要直接写入 assets/art/。只有主线任务完成规格、原创性、授权和运行时检查后，才会单独导入成品。

九、禁止事项

- 不复制或描摹商业游戏资源；
- 不使用来源不明的图片、字体、笔刷或素材；
- 不直接批量生成 15 名 NPC；
- 不制作完整四地图或矿洞战斗资源；
- 不修改项目代码、数据、场景、.meta 和权威文档；
- 不在用户未确认时自动选定、合并或定稿候选。

十、回传主线任务的信息

完成后请回传批次 ID、候选和确认结果、全部文件路径、色板、角色比例、Sprite/立绘一致性说明、工具与来源记录、许可证结论、待人工整理项目，以及允许主线安全导入的文件清单。
```
