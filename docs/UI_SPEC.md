# 《雾乡如昨》UI 规格

## 文档地位

本文件定义 Demo 的 UI 方向与首个对话界面约束。当前阶段只锁定规格，尚未制作正式 UI 图、字体资产或 Cocos 场景绑定。阶段 12A 先实现输入上下文、本地化和运行时 bootstrap，阶段 12B 再实现多档位迁移框架，阶段 12C 才实现标题、档位、HUD、设置与早期触控布局。

## 通用原则

- 逻辑设计分辨率为 `640×360`，横屏；UI 使用安全区与锚点适配，不拉伸像素资源。
- 标题和少量装饰文字可以使用明确授权的像素字体；中文正文、对白和设置使用清晰屏显字体。
- 微信版优先拇指操作，关键触控热区不小于 `56×56` 逻辑像素。
- 颜色不能成为唯一信息来源；选中、不可用、危险和确认状态同时使用边框、图标、文字或形状。
- UI 不直接决定耕种、关系、剧情或存档结果，只展示领域状态并提交语义命令。
- `wechat-low` 与 `pc-high` 保持相同布局和功能语义，只允许调整纹理规格、粒子、淡化和装饰效果。

## 对话界面

### 布局

第一版普通对话采用以下逻辑区域：

- 对白面板：距左右安全边界至少 `16`，距底部安全边界至少 `12`，建议高度 `112～128`。
- 姓名牌：位于对白面板左上区域，与正文具有明确层级；旁白不显示人物姓名牌。
- 正文：使用清晰中文字体，至少保留 2～3 行稳定区域；行距和字号必须在微信真机验证后锁定。
- 继续提示：位于对白面板右下，不遮挡末行文本；除了图标，还应提供可理解的动效或状态变化。
- 左立绘槽与右立绘槽：立绘底部可延伸到对白面板之后，但脸部、主要手势和关键效果不能被面板遮挡。
- 中央立绘槽：仅用于单人重点画面；普通双人对话不同时使用三个槽。

常规立绘显示高度建议为 `280～336` 逻辑像素。布局需要允许不同身高角色保持统一脚底/底边参考，同时让脸部处于接近的视觉阅读高度，不能简单把每张图强制拉伸成相同尺寸。

### 说话焦点

- 当前说话角色：100% 目标亮度与不透明度。
- 非当前角色：建议约 65%～75% 亮度和约 85% 不透明度；最终参数以手机可读性和肤色表现测试锁定。
- 优先使用统一 tint/透明度，不为 dim 状态复制纹理，也不依赖单角色 Shader。
- 旁白行默认不改变已有角色位置；可按对白舞台指令统一 dim，当前数据接口尚不提供复杂群像控制。
- 人物换边、离场和特殊剪影必须由明确数据或舞台指令触发，不能由渲染器猜测。

### 立绘切换

- 同一角色的表情、姿势、服装或效果变化使用约 `140ms` 轻量交叉淡化。
- 更换角色时可以使用短淡入淡出；禁止高成本模糊、景深、全屏扭曲或实时骨骼过渡。
- `reduceMotion` 或性能降级允许关闭/缩短淡化；最终立绘状态和对白时序必须保持一致。
- 连续快速推进对白时，新的目标状态覆盖尚未完成的过渡，不能排队播放过时表情。
- 立绘加载未完成时先保证姓名与对白可读；不能让一张图片阻塞整段对话。

### 输入与触控

- PC：确认键、取消键和选择键必须通过 `IInputService` 语义输入接入，具体按键在实现阶段确认。
- 微信：点击对白面板或明确的继续热区推进；选项使用独立大热区，不能依赖悬停。
- 对话开启时，世界移动和工具动作应被输入上下文抑制，避免推进对白同时锄地或播种。
- 快进、自动播放和历史记录不属于第一版必做项；若以后加入，不得绕过选择或不可逆调查确认。
- 对话选项、删除存档和不可逆调查确认必须使用不同视觉层级，避免快速点击误触。

### 安全区与横屏适配

- 所有正文、姓名、选项和确认按钮必须位于平台安全区内。
- 更宽屏幕优先增加两侧留白或立绘呼吸空间，不横向拉伸人物。
- 接近 16:9 的窄横屏优先缩减立绘露出宽度，不能压缩中文正文到不可读。
- 刘海、圆角和系统手势区域由平台安全区 adapter 提供；共享 UI 不直接访问 `wx` 或设备全局对象。
- 左右立绘可以延伸到安全区外的纯装饰区域，但脸部和关键手势必须留在安全区域内。

## 对话状态展示

对话表现读取 `docs/DIALOGUE_SPEC.md` 的规范化 `PortraitState`：

- `expression`、`pose`、`costume`、`effect` 决定资源映射；
- `direction` 决定画面朝向或独立方向变体；
- `dimmed` 是焦点表现覆盖值，不参与资源文件查找；
- 未指定状态时显示角色默认立绘；
- 缺失资源时按确定顺序回退，UI 不显示破损图标，也不中断正文。

关系状态和剧情状态只负责让对话系统选中不同对白行；UI 不从文字、好感数值或剧情标签自行推断表情。

## 视觉层级

从后到前建议为：

1. 游戏场景；
2. 对话期间可选的轻量场景压暗层；
3. 非当前人物立绘；
4. 当前人物立绘；
5. 对白面板与姓名牌；
6. 正文、选项和继续提示；
7. 仅用于确认或错误的模态层。

场景压暗层必须可关闭，且不能与角色 dim 叠加到看不清人物。微恐情境可以改变面板装饰、色调或有限效果，但正文对比度、输入反馈和确认语义不得降低。

## 字体与文本

- 正文使用动态或预生成字体时，必须覆盖 Demo 所有中文字符、标点和英文/数字混排。
- 对白 JSON 保存 `textKey`，本地化数据保存正文；UI 不把文本内容作为表情判断输入。
- 人名过长、三点省略号、引号、破折号和选项换行必须有样例测试。
- 不依赖纯像素小字号中文字体；真机上出现糊字或笔画粘连时优先提高可读性。

## 性能与画质开关

建议表现开关：

```text
portraitCrossFade
dialogueBackdropDim
portraitHighResolution
reduceMotion
```

| 能力 | `wechat-low` | `pc-high` |
| --- | --- | --- |
| 立绘资源 | 512×768 基线；内存不足时可映射 384×576 | 512×768 基线；未来可映射更高导出 |
| 同屏立绘 | 普通对话最多 2 张 | 第一版同样最多 2 张 |
| 焦点 dim | 简单 tint/透明度 | 简单 tint/透明度 |
| 表情切换 | 140ms 淡化，可关闭 | 140ms 淡化，可关闭 |
| Live2D/骨骼 | 关闭 | 第一版关闭 |
| 模糊/景深/高成本后处理 | 关闭 | 第一版关闭 |

资源切换时应释放不再需要的高分辨率纹理引用，并在角色目录层面预加载当前对话最可能使用的有限状态；具体 Bundle 与缓存策略在实现和微信真机剖析后确定。

## 首版验收

- 640×360 与另一横屏尺寸中，对白框、姓名、两名角色脸部和关键手势均在可读区域。
- 当前/非当前说话者明暗清楚，但非当前角色仍可识别。
- 同一段对白可多次切换表情和姿势，不闪烁、不错误保留上一角色。
- 未指定状态、缺少精确差分和缺失角色默认资源三类回退都有明确结果。
- 点击推进不会同时触发世界操作；按住或多点触控不会重复推进关键选择。
- `wechat-low` 关闭淡化和场景压暗后仍能完整阅读与操作。
- 场景像素 Sprite 与精美 2D 立绘能够被玩家认作同一人物。
- 正式资源均原创、明确授权或符合商业使用许可。
