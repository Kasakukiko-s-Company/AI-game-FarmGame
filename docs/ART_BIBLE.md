# 《雾乡如昨》Art Bible

## 文档地位

本文件是 Demo 正式美术生产基线。`docs/ART_GUIDE.md` 继续记录来源、审查和通用工作规则；具体尺寸、分层、色板、动画与效果规格以本文件为准。

正式美术方向命名为：

> **原创 HD 像素增强版**：高清像素角色 + 高清像素地图 + 轻量光照 + 粒子氛围特效 + 少量 Shader + 精美 2D 对话立绘。

这里的“HD”表示比基础瓦片拥有更高信息量的角色、建筑和界面资源，不代表模仿任何商业作品，也不代表完整 3D HD-2D 技术路线。

## 视觉原则

1. 游戏保持纯 2D 玩法和 2D TileMap；只用遮挡、分层、视差、光照 Sprite 和少量 Shader 制造轻量 2.5D 空间感。
2. 第一版玩家与 NPC 优先使用 `96×96` 单帧画布；`128×128` 只作为未来重新评估上限，不在同一角色资产中混用。
3. 地图基础瓦片固定为 `32×32` 像素；建筑、树木和大型装饰允许跨多个瓦片。
4. 场景内角色、地图、植物、建筑、作物、道具和 UI 使用原创高清像素美术，并在手机实际显示尺寸下优先保证轮廓识别；对话界面使用与场景角色设定一致的精美 2D 人物立绘。
5. 视觉增强只使用昼夜颜色层、假阴影、柔光 Sprite、轻量粒子、帧动画/UV 滚动和少量简单 Shader。
6. 所有效果都是表现层能力，必须可以按画质档位关闭，不得影响碰撞、交互、时间、天气、任务或叙事判断。
7. 微信和 PC 共享资产 ID、玩法坐标与动画语义；Steam 以后可以替换高规格资源或提高效果预算，但不能要求核心玩法代码分叉。
8. 不复制《星露谷物语》《八方旅人》或其他商业游戏的具体角色比例、地图、建筑、UI、调色和特效实现。
9. 所有素材必须原创、明确授权或满足商业使用许可，并登记到 `docs/ASSET_SOURCES.md`。

## 明确不采用

第一版不采用：

- 完整 3D HD-2D 场景；
- 3D 地形与依赖透视相机的核心地图；
- 实时动态阴影；
- 多个实时灯光；
- 景深；
- 体积雾；
- 高成本 Bloom；
- 大面积屏幕扭曲；
- 复杂水面反射；
- 每个物体独立 Shader；
- 超高分辨率角色动画。

以上能力即使未来在 Steam 版评估，也必须有关闭路径，并保持微信版核心画面可成立。

## 逻辑画布与像素规则

- 逻辑设计分辨率：`640×360`，横屏。
- 基础 Tile：`32×32`。
- 纹理采样：像素资源使用 Point/Nearest；禁止有意依赖双线性模糊掩盖像素问题。
- 像素缩放：世界像素资源优先采用整数缩放和像素对齐；不同宽高比通过视口与 UI 布局适配，不横向拉伸像素。
- 导出格式：运行时像素图优先无损 PNG；透明资源使用直边清晰的 RGBA。
- 图集安全：实际 padding/extrude 数值在 Cocos 样片验证后锁定；在锁定前不得批量打图集。
- 角色和大型物体统一使用底部中心作为地面接触基准，脚点不得随动画帧漂移。

## 角色规范

### 尺寸与比例

- 第一版单帧画布：`96×96`。
- 未来备选单帧画布：`128×128`，只有在 96×96 样片无法满足轮廓与动作需求时才整体升级。
- 人物比例：约 `3～4` 头身。
- 角色视觉高度不需要填满整张画布；必须为头发、工具和动作弧线保留透明空间。
- 碰撞体继续由玩法配置决定，不能从 Sprite 不透明像素自动推导。

### 可读性优先级

手机缩小后，识别顺序必须仍然成立：

1. 身体轮廓；
2. 发型或头部轮廓；
3. 服装主色块；
4. 一项代表性配饰；
5. 面部和衣物小细节。

禁止用大量单像素花纹、过密渐变和高频噪点代替造型。左右不对称配饰只有在手机尺寸下确实可读时才保留。

### 基础动画

- 四方向移动：`down`、`left`、`right`、`up`。
- 每方向先做 `4～6` 帧；首个样片推荐 6 帧，若移动节奏不需要则减少到 4 帧。
- 早期允许 `left/right` 镜像复用；当服装、配饰或工具方向造成明显错误时再拆分。
- Idle 每方向至少 1 帧；呼吸、眨眼属于后续可选增强。
- 工具动作使用独立动画。Demo 首批制作 `hoe`、`water`、`harvest`；`axe` 只在未来砍伐系统得到范围确认后制作，不因完整游戏愿景自动进入视觉包。
- 每个动作都要保持相同脚点、画布和方向顺序；工具命中时刻由动画事件或统一帧表定义，不能根据图片文件名猜测。

## 对话人物立绘规范

### 风格与一致性

- 游戏场景中的人物继续使用 `96×96` HD 像素 Sprite；进入对话时显示精美 2D 半身或膝上人物立绘。
- 立绘不是场景 Sprite 的放大版，但两者必须在发型、服装、配饰、年龄、体型、肤色和主配色上保持同一角色设定。
- 立绘采用清晰线稿、受控色块和轻量明暗，避免依赖复杂实时材质；日常与渗漏状态可以改变色调、服装或情绪差分，但不能无理由改变角色身份特征。
- 年龄会随长期世界日期增长。未成年角色满 18 岁并进入成年关系内容前，必须准备明确的成年场景 Sprite 与成年立绘版本；不得只把儿童素材放大、换表情或继续用于恋爱场景。
- 第一版只使用静态立绘差分，不实现 Live2D、复杂骨骼动画、逐句口型同步或每句对白一张全新完整插画。
- 重要剧情可以制作特殊姿势、服装或剧情状态立绘；这些资源仍必须通过稳定状态 ID 引用，并登记来源。

### 尺寸与导出

- 推荐源文件画布为 `1024×1536`、透明背景，保存在 `art-source`；构图必须允许从腰部以上安全裁切。
- 第一版公共运行时导出以 `512×768` 透明 PNG 为基线；在微信真机内存评估后，可以为 `wechat-low` 提供 `384×576` 映射，但不得改变对白数据中的角色或状态 ID。
- `pc-high` 可在未来映射到 `768×1152` 或更高导出；PC 高规格资源不能成为共享对话逻辑的依赖。
- 640×360 逻辑画布中的常规显示高度建议为 `280～336`，实际边界、遮挡和安全区遵循 `docs/UI_SPEC.md`。
- 立绘透明边缘必须干净，禁止在导出图内烘焙对白框、姓名牌、全屏色调或平台专属按钮。

### 差分层级

对话数据可以表达以下语义，资源映射决定最终使用哪张导出图：

- `expression`：面部表情，也可包含眼睛与嘴型差分；
- `pose`：身体姿势、手部动作和视线姿态；
- `costume`：服装、季节造型或剧情状态；
- `effect`：脸红、泪痕、怒气标记、面部阴影等有限情绪叠加；
- `direction`：画面内朝向 `left` 或 `right`；
- `dimmed`：对白焦点表现属性，不参与图片文件身份。

关系等级和剧情状态可以决定选中哪条对白，但最终对白必须显式指定需要的立绘状态。程序不得扫描对白文字并自动猜测“开心”“难过”等情绪。

### 第一版状态下限

核心角色至少准备以下八个可直接使用的常用状态：

1. `neutral`：普通；
2. `smile`：克制、礼貌的微笑；
3. `happy`：比微笑更外放的开心；
4. `shy`：害羞；
5. `angry`：生气；
6. `sad`：难过；
7. `surprised`：惊讶；
8. `thinking`：思考。

普通 NPC 第一版至少拥有 `neutral`、`happy`、`surprised`，以及 `angry` 或 `sad` 中至少一种。这里的“状态数”指审核通过的常用合成结果，不要求把所有表情、姿势、服装和效果做笛卡尔积。

### 制作与运行时策略

- 美术源文件推荐使用“基础身体/姿势 + 表情 + 有限效果”分层制作，减少重复修改。
- 第一版微信运行时优先导出每个常用状态一张合成 PNG，以降低节点数、Draw Call、组合错误和资源加载复杂度。
- 对话状态引用稳定语义 ID，再由角色立绘目录映射到资源；JSON 不直接写图片路径。
- 安全镜像的立绘可由 `direction` 水平翻转复用。不对称发饰、文字、徽记或手持物无法安全镜像时，必须提供独立方向资源，并在目录中显式映射。
- 当前说话者保持正常亮度；其他已显示角色由 UI 统一降低亮度或透明度。普通 dim 状态不需要另画一张图片。
- 表情或姿势切换只做短时淡入淡出；不得为这一步引入高成本后处理、全屏 Shader 或骨骼动画。

推荐源文件组织：

```text
art-source/portraits/{character_id}/
  base/
  expressions/
  effects/
  compositions/
```

`base` 保存基础身体与常用姿势，`expressions` 保存面部差分，`effects` 保存脸红、泪痕和阴影等有限叠加，`compositions` 保存审核通过的常用组合清单或可编辑合成文件。最终仍导出合成 PNG 到 `assets/art/portraits/{character_id}/`；不得把源分层直接当成运行时必须实时组合的节点树。

### 立绘命名

常规合成导出：

```text
portrait_{character_id}_{costume}_{pose}_{expression}.png
portrait_{character_id}_{costume}_{pose}_{expression}_{effect}.png
```

示例：

```text
portrait_npc_shen_he_default_default_neutral.png
portrait_npc_shen_he_default_hands_together_shy_blush.png
portrait_npc_shen_he_default_arms_crossed_angry_anger_mark.png
```

只有不能安全镜像时才增加方向后缀：

```text
portrait_npc_shen_he_default_default_neutral_left.png
portrait_npc_shen_he_default_default_neutral_right.png
```

`character_id`、`expression`、`pose`、`costume` 和 `effect` 都使用稳定英文 `snake_case`。缺失资源的确定性回退顺序和对话 JSON 契约见 `docs/DIALOGUE_SPEC.md` 与 `docs/DATA_SCHEMA.md`。

## 地图与环境规范

### 基础结构

- 使用 2D TileMap，不使用完整 3D 地形。
- 基础地表、道路和水体以 `32×32` Tile 组织。
- 小屋、树木、桥、屋檐和大型装饰可以跨多个 Tile，但底部占地、遮挡范围和碰撞范围必须分别定义。
- 地图装饰避免每格随机噪点；通过小规模变体、簇状分布、边缘 Tile 和可控装饰层形成自然感。

### 推荐渲染层顺序

从后到前：

1. `Ground`
2. `Ground_Detail`
3. `Water`
4. `Path`
5. `Objects_Back`
6. `Characters`
7. `Objects_Front`
8. `Effects`

说明：

- `Characters` 是角色渲染顺序的插入位置，不要求角色本身成为 TMX TileLayer。
- 树冠、屋檐、门框上沿等遮挡角色的内容放入 `Objects_Front`。
- 墙脚、树干根部、地面家具等角色应显示在其前方的内容放入 `Objects_Back`。
- `Effects` 只存放不影响玩法的雨、叶片、萤火、雾片和短暂异常效果。
- 现有不可见 `Blocking` 层继续作为技术碰撞层；后续可增加 `Interaction`/对象层，但不能让视觉层名称承担碰撞真相。

## 作物规范

- 作物仍以一个 `32×32` 玩法格为归属单位。
- 普通生长阶段优先使用 `32×32` 画布；成熟植株如需越界，可以使用 `64×64` 画布并保持底部中心脚点落在所属 Tile。
- 同一种作物的所有阶段保持根部位置一致，不能在成长时横向跳动。
- 当前雾叶草数据有三个可见 `stageIndex`，第一批资源使用 `stage_00`、`stage_01`、`stage_02`，其中最后一帧必须清楚表达成熟。
- 浇水、可收获和异常状态优先通过土地、轻量高光或小型反馈表达，不为每个状态复制完整作物图。

## 物品与 UI 规范

### 图标与格子

- 图标源画布推荐 `64×64`；简单物品允许 `48×48`，但同一套快捷栏不要混用不同视觉缩放。
- 默认快捷栏/背包显示格以 `48×48` 逻辑像素为基准，触控热区建议不小于 `56×56` 逻辑像素。
- 物品主体应占图标画布约 70%～85%，保留描边、数量角标和选中框空间。
- 数量、耐久或提示不能只靠颜色区分。

### 字体

- 标题、章节名和少量大字号装饰文字可以使用原创或明确授权的像素字体。
- 正文、对白、设置和小字号说明使用清晰的中文屏显字体，不强制像素化。
- 中文正文需在微信真机验证笔画、行高、标点和换行；不得为了像素风牺牲可读性。

## 调色板基线

以下是首个视觉验证包的语义色板，不是要求所有 Sprite 只能使用这些颜色。样片评审可以整体调整，但调整必须同步本表，避免各资产自行选色。

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `day_fog` | `#C9DDD2` | 白天远景雾与空气透视 |
| `grass_base` | `#639B6E` | 草地主色 |
| `grass_shadow` | `#416F55` | 草地、灌木阴面 |
| `soil_dry` | `#A7774F` | 普通泥土与道路 |
| `soil_tilled` | `#76503B` | 已耕土地 |
| `soil_wet` | `#4F4140` | 湿土，保留棕紫倾向而非纯黑 |
| `water_base` | `#4F91A4` | 日间水面 |
| `wood_base` | `#8A5B3E` | 木构建筑与家具 |
| `stone_base` | `#6E7875` | 石材中间色 |
| `warm_accent` | `#E5B85C` | 灯光、成熟提示、温暖焦点 |
| `magic_accent` | `#7E8CC7` | 魔法与轻微异常提示 |
| `ui_ink` | `#292B35` | 深色正文与描边 |
| `ui_paper` | `#E8DFC5` | 浅色面板与纸张 |

### 时间与异常覆盖层

- 白天：不使用强制全屏色偏，以基础色板为准。
- 黄昏：使用偏橙覆盖，起始参考 `#D88958`、约 12%～22% 强度。
- 夜晚：使用蓝紫覆盖，起始参考 `#39486F`、约 28%～38% 强度；局部暖光承担视觉焦点。
- 雨天：降低饱和度并略微偏冷，不能把所有可交互物压成同一灰度。
- 结界渗漏：在正常时间状态之上加入低饱和蓝灰/灰紫偏移和有限异常强调色，不直接使用全屏纯黑或血红。

覆盖值是样片起点，最终以微信真机和 PC 屏幕实测为准。

## 光照方向

- 全局主光默认从画面左上方向右下照射。
- Sprite 的顶部和左上边缘使用较亮色，底部和右下侧使用阴影色。
- 角色脚底使用半透明椭圆假阴影，中心位于脚点正下方，不随头发或工具扩大。
- 建筑、树木和大型道具的投影方向保持右下，但第一版不绘制长距离实时动态阴影。
- 路灯、窗户和篝火使用加法/柔光 Sprite 或白名单简单 Shader；局部发光允许覆盖全局方向，但不改变碰撞或可交互判断。

## 轻量环境效果

第一版允许：

- 昼夜颜色覆盖；
- 角色和关键物体的假阴影；
- 路灯、窗户、篝火的柔光 Sprite；
- 雨滴、雪花、落叶、花瓣和萤火虫的轻量粒子；
- 水面的少量帧动画或单次 UV 滚动；
- 草摆动、树叶轻晃、烟囱冒烟和河流闪光；
- 为全局色偏、水面或单个关键异常准备的少量共享 Shader。

所有动态效果必须有屏幕内数量预算、裁剪策略和关闭路径。能用共享材质或批处理完成时，不为每个物体创建独立材质实例。

## Sprite Sheet 布局

### 角色 Sheet

- 每帧固定 `96×96`。
- 行顺序固定：`down`、`left`、`right`、`up`。
- 列按时间从左到右：`00`～`05`；少于 6 帧时不填充无意义重复帧。
- 每个动作使用独立 Sheet，避免一个超大 Sheet 混入无关状态。
- 若左右镜像，源 Sheet 可以只保存 `right`，但导出清单和运行时映射必须明确记录镜像规则。

示例：

```text
player_male_idle.png
player_male_walk.png
player_male_hoe.png
player_male_water.png
player_male_harvest.png

player_female_idle.png
player_female_walk.png
player_female_hoe.png
player_female_water.png
player_female_harvest.png
```

男性/女性主角形态共享帧尺寸、动作语义、脚点、碰撞和工具时序，只替换视觉与显式称谓/对白差分。第一批视觉验证包仍只制作当前男性形态；女性形态需在后续独立资源任务中按同一规格制作，本阶段不自动扩大美术范围。

未来若确认砍伐系统，再按相同规范增加 `player_{gender_form}_axe.png`。

### 地图与作物 Sheet

- Tileset 以 `32×32` 网格排列；同一文件内不混入不同 Tile 尺寸。
- 自动地形边缘、角落和变体按连续区块排列，并在源文件旁保存布局说明。
- 作物按生长阶段从左到右排列；越界成熟帧单独使用 64×64 Sheet 或独立文件。

## 命名规范

- 文件和目录使用小写英文 `snake_case`。
- 稳定格式：`{subject}_{action}_{direction}_{frame}`。
- 方向：`down`、`left`、`right`、`up`。
- 帧号：两位数字，从 `00` 开始。
- 生长阶段：`{crop_id}_stage_00.png`，例如 `mistleaf_stage_00.png`。
- 地图图集：`{area_id}_{category}_tileset.png`。
- UI：`ui_{screen_or_group}_{element}_{state}.png`。
- 对话立绘：`portrait_{character_id}_{costume}_{pose}_{expression}[_effect].png`；不能安全镜像时在末尾增加 `left`/`right`。
- 特效：`fx_{effect_id}_{variant}.png`。
- 材质：`mat_{purpose}.mtl`；Shader：`shader_{purpose}`，实际扩展名遵循 Creator 3.8.8 支持格式。

用户可见显示名与文件 ID 分离；改变中文名称不要求重命名稳定资源 ID。

## 源文件目录

```text
art-source/
  concepts/
  ai-generated/
  aseprite/
  portraits/
  exports/
```

- `concepts`：自制草图、色稿、角色设定和构图研究。
- `ai-generated`：仅存放有生成记录、可追溯输入来源的探索稿，不直接作为最终运行时素材。
- `aseprite`：Aseprite 或其他可编辑像素源文件。
- `portraits`：对话立绘的可编辑分层源文件、差分与合成记录；不直接由 Cocos 导入。
- `exports`：待审核导出区；通过尺寸、命名、来源和视觉检查后再复制到 `assets/art`。

## 画质档位与效果开关

### 架构原则

- 画质默认值由运行环境选择，用户设置可以覆盖。
- 画质配置只控制表现层；玩法系统不得读取粒子数量、Shader 开关或灯光状态。
- 每个效果具有独立开关，档位只是开关和预算的预设组合。
- 所有平台使用相同逻辑资产 ID。未来 PC 高分辨率替换通过资源映射或 Bundle 完成，不修改作物、NPC、交互和存档 ID。
- 自动降级只能降低表现，不改变天气、时间和异常事件是否发生；关闭雨粒子后仍要通过 UI/音频表达“正在下雨”。

### 建议开关

```text
timeColorOverlay
fakeCharacterShadows
localLightSprites
weatherParticles
ambientParticles
vegetationMotion
waterAnimation
simpleSharedShaders
anomalyPostEffect
```

## 第一批视觉验证包

只制作以下五类正式资源：

1. 一个 96×96 玩家角色；
2. 一套 32×32 草地与泥土地块；
3. 一栋小屋；
4. 一棵树；
5. 雾叶草的完整成长阶段。

使用这批资源搭建同一个小场景，并验证四种环境状态：

- 白天；
- 黄昏；
- 夜晚；
- 下雨。

阶段 10D 已把第一处异常锁定为旧界碑后的“道路回折”。同一场景必须以相同 16:9 机位验证 `visual_target.boundary_day_normal` 与 `visual_target.boundary_first_fold`：日常态的道路看似通向山外，异常态让玩家越过界碑后再次在前方看见同一界碑，并以返回的路标布留下线索。只允许有限冷暗覆盖、轻雾、界碑/路标布状态替换、UI/声音变化，不复制整套地图资源；完整构图、语义 ID、性能回退与禁止内容见 `docs/FIRST_BARRIER_ANOMALY.md`。

在该场景通过风格、遮挡、手机可读性、光照、粒子和性能评审前，不批量生产 NPC、建筑、作物、家具或完整地图。

对话立绘不计入上述五类场景视觉验证资源。五类资源通过且阶段 10C 已锁定试制角色后，才为一名核心角色制作“立绘试制包”，验证 `512×768` 合成 PNG、八个常用状态、双人明暗焦点和微信内存，再开始批量制作 NPC 立绘。

## 验收清单

- 玩家在 640×360 和另一横屏尺寸下仍能通过轮廓、发型、主色和配饰识别。
- 行走与 Demo 三类工具动作脚点稳定，方向和命中帧明确。
- 小屋与树分别验证 `Objects_Back`/`Objects_Front` 遮挡。
- 草地、泥土和作物遵守 32×32 网格，不出现接缝、模糊和根部跳动。
- 白天、黄昏、夜晚、下雨具有明显但不过度的差异。
- `wechat-low` 关闭增强效果后仍可读、可玩、能理解时间和天气。
- `pc-high` 不改变玩法坐标、资源 ID、存档或输入逻辑。
- 同一角色的像素 Sprite 与对话立绘在发型、服装、配饰、年龄、体型和配色上能够互相识别。
- 一名核心角色的八个常用状态在手机尺寸下表意清楚；表情、姿势连续切换只使用轻量淡入淡出。
- 缺失精确立绘状态时按文档顺序回退，不能因资源缺失中断对白，也不能从文字自动猜测替代情绪。
- 素材来源、源文件、导出记录和许可证齐全。
