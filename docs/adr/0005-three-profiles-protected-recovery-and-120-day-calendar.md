# ADR-0005：三档存档、受保护恢复点与 120 日历法

## 状态

提议，等待阶段 10E 用户验收

## 背景

技术 MVP 当前只有一个固定 `autosave`，只在成功睡觉后写入。Demo 需要标题与档位界面，也需要为未来不可逆真相线提供可恢复保障；与此同时，角色年龄会随世界日期变化，乔苓必须在经过一个完整游戏年后从 17 岁进入成年规则。如果不先锁定档位、恢复点和历法，阶段 12B、13～15 会分别引入不兼容的存档与日期语义。

## 决策

Demo 使用三个独立玩家档位。每个档位拥有一份普通自动保存的当前快照，并为未来不可逆调查预留一份同档受保护恢复快照。三个档位解决不同游玩档案，保护快照解决“进入不可逆内容后仍可回到确认前”的安全需求，两者不能互相替代。

当前 Demo 不进入不可逆真相期，因此保护快照保持为空；第一处“界碑回折”安全可返回，只更新当前快照。首次加入不可逆调查的版本必须在确认前成功写入并验证保护快照，否则不允许进入。

“继续游戏”使用最近成功进入的档位。最近档损坏时进入档位管理并报告错误，不静默加载另一个档位。三个档位分开存储，摘要可从快照重建；一个损坏档不会阻塞其他档位。

技术 MVP 的旧 `autosave` 通过显式、全有或全无的迁移导入第一个空档。旧世界坐标固定回退到正式住宅床铺；旧 10×10 农田通过阶段 11 锁定的命名导入区域做相对坐标平移。任一状态无法安全映射时整次迁移失败并保留旧载荷，不静默丢弃部分进度。

世界历法固定为四季、每季 30 天、每年 120 天。开场为第 1 年春季第 1 日，存档只保存一基累计 `worldDay`。年份、年内日、季节、季内日和年龄均由同一个历法服务推导。乔苓的生日序号与开场日相同，因此她在 `worldDay=121` 满 18 岁。

Demo 达成第一处异常里程碑后自动保存并允许玩家继续自由生活或返回标题，不强制结束当前档。

天气和日内时段只作为阶段 11 的视觉验证预设，不进入 SaveData v2 或玩法结算。

阶段 10E 后续范围变更已通过 ADR-0006 把固定旧矿道与最小战斗切片加入 Demo。SaveData v2 因而同时保存玩家生命和当前 `worldDay` 的矿洞运行状态；完整规则由 `docs/MINE_COMBAT_SLICE.md` 决定，不在本 ADR 中重复定义战斗数值。

## 后果

### 正面

- 三个玩家档案、最近档位和损坏隔离有确定交互，不再依赖单槽假设。
- 不可逆内容在未来具备强制恢复护栏，但当前 Demo 不为一个可返回事件制造虚假警告。
- v1 到 v2 的迁移可以用真实旧存档做全事务测试，不靠坐标猜测。
- 年龄、生日、季节显示与跨天结算共享一个确定历法，长期档不会因重读产生不同结果。
- 天气和时钟不再作为模糊“可能加入项”；矿洞与战斗则由独立 ADR 和验收边界控制，不再无界扩张。

### 代价

- 阶段 12B 需要档位容器、摘要重建、全局最近档、迁移和损坏隔离测试，不能直接复制现有 `AutosaveSession` 三次。
- 阶段 11 必须为旧 10×10 农田提供一个可验证的命名导入区域。
- 保护快照虽然当前为空，档位 UI 和数据接口仍需区分它与普通自动保存。
- Demo 暂不提供系统性昼夜、天气或完整矿洞生态；固定旧矿道与最小战斗切片之外的深度仍需后续单独扩展。

## 被否决的替代方案

### 继续使用一个自动存档槽

实现最省事，但无法支持多个玩家档案，单个损坏存档也会阻塞整个应用，不适合公开 Demo。

### 只增加三个档位，不提供保护快照

不能保证玩家在进入不可逆调查前主动复制档位，也不能防止三个档位都已使用，因此不构成可靠恢复保障。

### 最近档损坏时自动加载另一个档位

看似方便，却可能让玩家误以为进度回退或进入错误角色档案。明确进入档位管理更安全。

### 同时加入连续时钟、随机天气和完整矿洞生态

会同时扩大 NPC 日程、农田结算、输入、UI、存档、地图与平台生命周期范围。当前只接受 ADR-0006 锁定的固定单层矿洞和最小战斗闭环，不接受随机楼层、Boss、装备或经济系统。
