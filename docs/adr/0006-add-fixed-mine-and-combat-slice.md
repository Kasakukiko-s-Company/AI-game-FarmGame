# ADR-0006：增加固定旧矿道与最小战斗切片

## 状态

提议，等待阶段 10E 用户验收

## 背景

阶段 10B 把当前 Demo 限定为住宅、故乡主区域和结界边界三张玩法地图，阶段 10E 初稿进一步排除了矿洞和战斗。用户随后明确要求把矿洞与战斗加入 Demo。若只增加一个矿洞名词而不同时冻结地图、输入、生命、失败、背包和存档规则，阶段 11、12、15 与双平台验收会各自形成不兼容实现。

## 决策

当前 Demo 增加第四张固定玩法地图 `old_mine`。它通过 `hometown_main` 的受控入口双向连接，不与 `home_interior` 或 `boundary_pass` 直连，也不作为第一处结界异常或主线调查的前置条件。

矿洞只实现一层手工灰盒、一类可破坏矿脉、一种原创矿石物品、一类基础敌人与一场固定遭遇。玩家使用快捷栏选中的锄镐执行相邻格采矿，使用学院练习杖执行面向方向的基础攻击；两者复用统一 `primaryAction` 语义，不为 PC 和微信各写一套玩法规则。

玩家具有 5 点权威生命。敌人接触造成 1 点伤害并触发短暂无敌窗口。生命降到 0 时不死亡、不丢物品、不推进日期，而是完成一次原子安全撤离：抑制输入、回到 `mine_safe_return`、恢复生命并保留当日已经采空的矿脉与已完成遭遇，防止重复刷取。睡觉进入下一天时重置当日矿洞运行状态并恢复生命。

SaveData v2 明确保存玩家生命以及当前 `worldDay` 对应的矿洞运行状态，包括稳定矿脉 ID 与固定遭遇 ID。存档不能保存攻击帧、击退、无敌计时或敌人临时坐标；加载时在安全规则下重建表现与敌人位置。

矿洞切片不连接战争残响、亡灵、愿境或第一处结界异常。普通敌人是当前世界内的魔法生态威胁，不是死者灵魂，也不是第一愿望固定的战争残响。

正式矿洞美术、敌人动画、音乐、环境声和战斗音效不在主开发任务中创作。玩法灰盒通过后，按 `docs/RESOURCE_CREATION_WORKFLOW.md` 分别建立视觉与音频资源任务。

## 后果

### 正面

- Demo 同时证明耕种日常、关系内容、可选外出采集和基础战斗，而不是只描述完整产品愿景。
- 固定单层、固定遭遇和确定掉落可以用纯规则测试和稳定存档复现，适合微信与 Windows 双平台。
- 矿洞不驱动悬疑主线，玩家仍可长期停留在平静日常，也可以完全忽略矿洞。
- 采矿和攻击共享快捷栏与语义输入，不增加平台专属业务分支。

### 代价

- 阶段 11 需要完成第四张地图的灰盒、入口、碰撞、相机和加载预算。
- 阶段 12B 的 SaveData v2 必须在首次实现时包含生命和当日矿洞状态，不能等战斗完成后再临时塞字段。
- 阶段 15 需要先做采矿/战斗灰盒闭环，再实现第一处结界异常；阶段 16 还要增加矿洞正式资源生产与性能回归。
- 微信触控、HUD、安全区和前后台输入释放必须覆盖战斗场景。

## 被否决的替代方案

### 只在对白或背景中暗示矿洞

不满足“将矿洞、战斗加入”的要求，也无法验证玩法、输入、存档和性能。

### 随机楼层和无限矿洞

会同时引入程序生成、楼层存档、资源经济、难度曲线和大量内容，不适合作为当前 Demo 的代表性切片。

### 直接加入 Boss、装备与掉落经济

会让战斗依赖商店、数值养成、装备 UI 和完整怪物生态。当前切片只证明基础移动、攻击、受伤、击败、采矿与安全撤离。

### 生命归零后跨天并扣除物品

会把失败处理绑定农田成长、生日事件和背包损失，增加意外惩罚与恢复复杂度。Demo 先采用无物品损失、无日期推进的安全撤离规则。
