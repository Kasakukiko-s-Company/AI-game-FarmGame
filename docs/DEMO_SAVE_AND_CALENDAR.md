# 《雾乡如昨》Demo 存档、历法与结束方式规格

## 文档地位

本文件是阶段 10E 的权威决策规格，定义 Demo 的三档存档、旧单槽迁移、损坏档隔离、未来调查前恢复点、阶段性结束方式、世界历法，以及天气和日内时段边界。阶段 10E 后续加入的矿洞/战斗存档语义与本文件共同生效，玩法细节见 `docs/MINE_COMBAT_SLICE.md`。

对应架构决策记录为 `docs/adr/0005-three-profiles-protected-recovery-and-120-day-calendar.md`；在用户完成阶段 10E 验收前，ADR 状态保持“提议”。

阶段 12B 的存档迁移与档位框架、阶段 13～15 的关系/日期/叙事状态、阶段 20 的 Demo 收尾都必须以本文件为输入。当前技术事实仍是 SaveData v1 的单一 `autosave`；本文件描述的是已锁定但尚未实现的 Demo 目标，不能把计划误写成现有能力。

## 已锁定结论

- Demo 必须提供三个彼此独立的玩家档位。
- 每个档位只有一份持续自动更新的当前快照；Demo 不提供任意数量的手动存档、复制档位或档位改名。
- “继续游戏”指向最近使用的档位；该档损坏时进入档位管理并明确报错，不能静默加载另一名玩家的档位。
- 单个档位损坏不得阻塞其他档位，也不得被新游戏或其他档位的自动保存覆盖。
- 技术 MVP 的旧 `autosave` 通过一次显式迁移导入空档位；未经验证不得删除或覆盖旧载荷。
- 三个普通档位不能替代未来不可逆调查前的受保护恢复点。
- 当前 Demo 不进入不可逆调查期，因此不会创建受保护恢复点；但阶段 12B 必须保留快照角色与 UI 状态接口。
- 第一处“界碑回折”不是不可逆调查点，不创建受保护恢复点。
- 第一处异常完成后显示非阻塞 Demo 里程碑；玩家可以继续自由生活，也可以保存后返回标题。
- 世界历法采用四季、每季 30 天，共 `120` 天一个游戏年；开场是第 1 年春季第 1 天。
- SaveData v2 只保存权威累计 `worldDay`，年份、季节和年内日都由历法配置确定性推导。
- 阶段 11 的白天、黄昏、夜晚和下雨只属于视觉验证状态；当前 Demo 不实现连续日内时钟、随机天气或天气玩法。
- 当前 Demo 增加固定单层 `old_mine` 与最小采矿/战斗切片；SaveData v2 保存玩家生命和当前日矿洞状态，但不加入随机楼层、Boss、装备或完整经济。

## 存档拓扑

### 三个玩家档位

稳定档位 ID 为：

```text
profile-1
profile-2
profile-3
```

数字是 UI 顺序，不是数组下标。领域代码传递稳定档位 ID，不传 Cocos 节点、文件路径、平台存储键或页面按钮引用。

每个档位逻辑上包含：

```text
ProfileSlot
├── metadata
├── currentSnapshot
└── protectedRecoverySnapshot?   # 当前 Demo 保持为空
```

- `metadata` 用于档位列表摘要，不是第二份玩法权威状态；摘要可由当前快照重建。
- `currentSnapshot` 是该档位唯一会被普通自动保存更新的权威快照。
- `protectedRecoverySnapshot` 只供未来不可逆调查使用，普通自动保存、继续自由生活和新一天结算都不能覆盖。
- 用户设置与 `lastPlayedProfileId` 属于全局应用数据，不放进任一玩法档位；切换档位不能改变语言、音量、画质或无障碍设置。

### 档位摘要

档位界面至少展示：

- 档位编号；
- 空档、可读取、损坏、版本不支持或读取失败状态；
- 世界日期；
- 最近保存时间；
- 当前地图的本地化名称；
- 是否达到第一处异常里程碑；
- 未来若存在受保护恢复点，显示其世界日期与创建原因。

摘要不得显示幸存者/重构村民分类、知情层级、愿境或三个愿望等内部信息。摘要损坏时允许从快照重建；摘要文件不能成为三个档位共同失效的单点。

## 标题界面与继续游戏

标题界面的最小入口为：

1. **继续游戏**：读取 `lastPlayedProfileId` 指向的当前快照；
2. **新游戏**：进入档位界面并选择空档；
3. **读取游戏**：查看三个档位及其状态；
4. **设置**；
5. **退出游戏**：仅 Windows 显示，微信不伪造退出应用能力。

规则：

- 没有可用档位时隐藏或禁用“继续游戏”，并把焦点放在“新游戏”。
- 最近档位损坏、版本不支持或读取失败时，“继续游戏”进入档位界面并聚焦该档，显示明确原因；不能自动跳到另一个档位。
- 从“读取游戏”选择其他有效档位后，只有成功读取并进入稳定场景才更新 `lastPlayedProfileId`。
- 删除档位需要二次确认，明确显示档位编号、日期和不可恢复提示；长按、双击或快速连续触控不能绕过确认。
- 损坏档允许删除，但删除前必须让玩家知道其他档位不受影响；当前 Demo 不提供修改 JSON、在线修复或云端找回。

## 自动保存事务

### 创建新档

玩家选定空档并确认新游戏后，先建立可验证的开场快照，再进入 `home_interior`。若首次写入失败，不得显示为已经创建成功，也不能占用其他档位。

### 稳定保存点

当前 Demo 只在下列稳定边界更新 `currentSnapshot`：

1. 创建新档并完成开场状态初始化；
2. 成功睡觉、跨天结算、生日事件计算和出生点传送全部完成之后；
3. 第一处“界碑回折”安全落到 `boundary_return`、稳定叙事状态全部提交之后；
4. 玩家从暂停菜单选择“保存并返回标题”，且当前没有对白、地图切换或异常演出事务。

普通移动、工具动作、背包选择、单句对白推进和普通地图切换不会单独写盘。平台进入后台时可以请求一次最佳努力保存，但只有运行时声明“当前处于稳定可捕获状态”时才能执行；微信和 Windows 的生命周期保证在各自平台阶段验证，不能把后台回调当作唯一可靠保存点。

写入继续遵守“编码与完整校验成功后再替换”的事务规则。任何捕获、编码、平台写入或回读验证失败都保留原 `currentSnapshot`。

## 单档损坏隔离

- 三个档位与全局设置使用不同语义键，禁止把三个快照嵌入一个必须整体解析的大 JSON。
- 档位目录/最近档位索引损坏时，应扫描三个稳定档位 ID 重建摘要，不能把全部档位判为丢失。
- 当前档位损坏后，该档位的普通写入保持锁定，直到玩家明确删除、成功迁移，或未来从受保护恢复点恢复。
- 另一个档位的新建、读取和保存必须继续可用。
- 存储配额、权限或平台读取失败与“空档”是不同状态，不能提示玩家直接覆盖。

## 旧单槽迁移

### 迁移入口

阶段 12B 首次打开档位界面时检测旧语义槽 `autosave`。检测到后显示一次“发现旧技术测试存档”入口，由玩家选择导入或暂不处理；不能在后台自动占用档位。

导入目标使用第一个空档，优先顺序为 `profile-1`、`profile-2`、`profile-3`。若三个档位都非空，只提示需要先释放档位，不覆盖任何现有档。

### v1 到 v2 的确定迁移

有效 SaveData v1 按以下规则迁移：

- `currentDay` 迁移为同值 `worldDay`；由于开场日为世界第 1 天，不需要模糊的日期偏移。
- 背包与快捷栏在物品目录校验通过后保留。
- 玩家固定落到 `home_interior/home_bed`，保留朝向只在值仍合法时使用；旧 `mvp_farm` 世界坐标不得投影到正式地图。
- 阶段 11 为 `hometown_main` 指定一个至少 `10×10` 的旧农田导入区域。旧 `mvp_farm` 的 `(5,5)～(14,14)` 以相对坐标平移到该区域；已耕地、湿土和作物只有在目标格可耕、作物目录仍有效且全部事务可验证时才整体迁移。
- 若新地图没有完整导入区域或任一农田状态无法安全映射，本次导入失败并保留旧档；禁止悄悄丢弃部分作物后声称迁移成功。
- v1 不存在的角色身份、关系、目标和叙事状态使用开场默认值，不能根据玩家已有天数猜测剧情已经发生。

只有 v2 目标档完成写入、回读、解码与运行时恢复计划验证后，才记录“已迁移”标记。旧 `autosave` 保持只读，不立即删除；档位界面不再反复弹窗，但设置/存档管理可以提供明确的“删除旧测试存档”操作。

## 受保护的调查前恢复点

三个普通档位解决不同游玩档案，不解决不可逆调查。未来首次加入不可逆真相内容时，必须同时实现以下流程，否则该内容不得发布：

1. 在明确确认界面之前，捕获当前档位的稳定快照；
2. 写入并回读验证 `protectedRecoverySnapshot`；
3. 只有验证成功后才允许玩家确认进入不可逆内容；
4. 后续普通自动保存只更新 `currentSnapshot`；
5. 档位界面提供“返回调查前”入口，并再次显示会覆盖当前进度的确认；
6. 恢复成功后是否保留原保护点由未来真相线规则明确决定，不能由存储 adapter 自行删除。

当前 Demo 的第一处异常完全可返回日常，因此：

- 不显示不可逆警告；
- 不创建保护点；
- 不把 `mystery.firstBarrierObserved` 当作真相期入口；
- SaveData v2/档位容器只预留快照角色和空状态，避免以后重写三档结构。

## Demo 阶段性结束方式

第一处异常安全结束并提交 `demo.milestoneReached=true` 后：

1. 完成一次稳定自动保存；
2. 返回日常主区域时显示一次非阻塞“Demo 主要内容已体验”卡片；
3. 提供“继续生活”和“返回标题”两个清楚入口；
4. 默认焦点为“继续生活”，不能倒计时、强制退标题或销毁当前档；
5. 选择继续后，玩家可以无限期耕种、睡觉和进行已开放的关系互动；日期不会自动推进新的悬疑阶段；
6. 选择返回标题只切换应用状态，不创建结局、不播放核心真相字幕，也不把档位标记为通关后不可使用。

该卡片每档只自动显示一次；以后可以从暂停菜单查看 Demo 进度说明。反馈问卷、商店页或愿望单入口属于发行阶段，不能阻塞返回游戏或读取存档。

## 世界历法

### 权威配置

```text
seasons = spring, summer, autumn, winter
daysPerSeason = 30
daysPerYear = 120
openingYear = 1
openingDayOfYear = 1
openingWorldDay = 1
```

玩家可见开场日期为“第 1 年·春·第 1 日”。`worldDay` 是从开场开始的一基累计天数，是存档中的唯一权威日期计数。

### 推导公式

对于合法 `worldDay >= 1`：

```text
zeroBasedDay = worldDay - 1
year = floor(zeroBasedDay / 120) + 1
dayOfYear = (zeroBasedDay % 120) + 1
seasonIndex = floor((dayOfYear - 1) / 30)
dayOfSeason = ((dayOfYear - 1) % 30) + 1
```

`seasonIndex` 依次映射到春、夏、秋、冬。UI、作物条件、生日和叙事查询都从同一历法服务读取，不能分别实现日期算法。

### 跨天顺序

成功睡觉按以下事务顺序执行：

1. 结算旧日的浇水与作物成长；
2. 把 `worldDay` 增加 1；
3. 计算新日期；
4. 生成且只生成一次该日生日/成年事件；
5. 重置新日瞬态状态并传送到出生点；
6. 所有步骤成功后自动保存。

任一步失败都不能留下“日期已加但成长或生日未结算”的半状态。生日事件使用人物 ID、目标 `worldDay` 和事件类型形成幂等键，读档或重试不能重复加年龄或重复发奖励。

### 年龄语义

- `ageAtOpening` 表示开场时已经成立的年龄。
- 当前年龄等于 `ageAtOpening` 加上 `(openingWorldDay, currentWorldDay]` 区间内跨过的生日次数。
- 开场日自身不重复触发生日。
- 乔苓 `ageAtOpening=17`，其 `birthdayDayOfYear=openingDayOfYear=1`；她在 `worldDay=121` 进入第 2 年春季第 1 日时满 18 岁。
- 成年事件只改变年龄查询和允许进入的后续内容；不会自动告白、自动建立 `dating` 或把儿童期对白改写成恋爱对白。

其他角色生日在阶段 13 角色数据落地前逐一确认；所有生日序号必须位于 `1～120`。

## 天气与日内时段

阶段 11 仍要制作同一场景的白天、黄昏、夜晚与下雨视觉验证，但它们当前是表现配置，不是 Demo 权威玩法状态：

- SaveData v2 不保存 `timeOfDay`、`dayPhase` 或 `weatherId`。
- Demo 不运行连续时钟，不因站立或暂停消耗游戏时间。
- Demo 不随机生成天气，雨景不会自动浇水、改变 NPC 日程或作物成长。
- 剧情或视觉测试可以显式加载某个表现预设，但退出测试/剧情后回到正常日常表现，不改变世界日期。
- 画质开关可以关闭雨粒子、灯光和色层；未来若天气升级为玩法，画质仍只能改变表现，不能改变权威天气结果。

若试玩证明昼夜或天气是 Demo 核心体验，必须提交新的范围变更，同时定义时间推进、暂停、睡觉、雨天浇水、NPC 日程、存档字段和跨平台前后台行为；不能只增加一个计时器。

## 矿洞、生命与当日运行状态

阶段 10E 已通过 ADR-0006 增加第四张固定地图 `old_mine`。SaveData v2 必须在首次实现时加入：

- `playerVitals.health` 与固定 `maxHealth=5`；稳定快照中的生命必须位于 `1～5`；
- `mineRun.mapId='old_mine'` 与 `mineRun.worldDay`；
- 同日已采空的稳定 `brokenNodeIds`；
- 同日已完成的稳定 `defeatedEncounterIds`。

不保存矿脉剩余命中次数、敌人当前生命/位置、投射物、冷却、无敌计时、击退或表现状态。加载时未完成对象从定义状态重建；非法矿洞位置回退到 `mine_safe_return`。睡觉结算新日时清空矿洞运行状态并恢复满生命，随后与世界日期一起原子保存。

生命归零不允许成为可保存半状态：必须先安全撤离到 `mine_safe_return`、恢复生命，并保留当日已完成 ID，再允许保存。完整事务、输入和明确不做项见 `docs/MINE_COMBAT_SLICE.md`。

## 阶段 12B 实现输入

阶段 12B 需要实现并测试：

- 三个稳定档位与可重建摘要；
- 全局 `lastPlayedProfileId` 和全局设置隔离；
- 当前快照的读取、事务写入、删除与损坏隔离；
- v1 `autosave` 的显式、全有或全无迁移；
- SaveData v2 的 `worldDay`、地图/锚点、关系/目标/叙事状态容器；
- SaveData v2 的玩家生命、当日矿洞状态、稳定矿脉/遭遇 ID 校验与 v1 默认值；
- 空的受保护恢复点角色和 UI 状态，不创建虚假恢复快照；
- 新游戏、继续最近档、读取指定档和保存并返回标题的应用流程。

阶段 12B 不实现最终真相、云存档、档位复制、档位改名、任意手动存档、天气、连续时钟或实际战斗运行时；它只提前落地已冻结的矿洞存档字段与迁移。真实采矿/战斗在阶段 15A 接入。

## 验收清单

- 三个档位可以分别新建、保存、读取和删除，彼此状态不串档。
- 最近档位只在成功进入游戏后更新；损坏时不静默跳档。
- 一个损坏档不阻塞另外两个档位。
- 旧 `autosave` 只有在目标 v2 完整验证后才标记迁移成功，失败不丢旧载荷。
- `worldDay=1`、`30`、`31`、`120`、`121` 的年份/季节/日期结果正确。
- 乔苓在 `worldDay=120` 仍为 17 岁，在 `worldDay=121` 为 18 岁；重读与重试不重复成年事件。
- 第一处异常完成后保存一次并允许继续生活；不创建调查前恢复点。
- Demo 里程碑卡片不强制退标题，后续睡觉不自动进入真相线。
- SaveData v2 不包含天气或日内时钟字段。
- `old_mine` 存档恢复能保持生命、已采矿脉和已完成遭遇；新日重置后不会读回旧日状态。
- 四张地图之外没有额外矿层、秘境或战斗入口。
