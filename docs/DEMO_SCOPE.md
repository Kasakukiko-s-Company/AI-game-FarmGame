# 《雾乡如昨》游戏 Demo 范围

## 里程碑定义

当前目标是一个可公开试玩、能够代表最终游戏气质的原创 Demo，不再限定固定游玩时长。

Demo 应同时证明三件事：

1. 表层日常本身足够舒适，耕种与村庄生活可以成立；
2. 村民不是功能按钮，玩家能够对至少一部分人物产生兴趣和感情；
3. 第一处结界异常能自然地把玩家引向悬疑，但不会强迫不想调查的玩家进入真相线。

Demo 的实际时长由内容密度和试玩结果决定，不以凑满或压缩到固定分钟数为验收标准。

## 开场位置

- 游戏直接从第一章开始。
- 主角在故乡家中醒来，只记得从秘境取得神石后昏倒。
- 记忆封印从取得神石后的灾难开始；主角仍记得学院封校、回乡生活以及袭击前与村民的关系。玩家没有亲历这段过去，需要通过重逢对白逐步理解。
- 村长解释有人发现昏迷的主角并将其送回。
- 学院封校、先前真实田园生活、秘境、军队袭击和许愿都不作为序章展示，而留给后续倒叙章。
- 技术 MVP 的房屋不可进入只是占位限制。Demo 必须提供一个最小住宅室内地图，承载醒来、首次对白、基础移动提示和离开住宅；不能用屋外睡觉点代替第一章开场。

## 地图数量与职责

阶段 10B 已锁定当前 Demo 使用三张可独立加载的玩法地图；标题、档位、设置与暂停属于应用 UI，不计入地图数量：

1. **`home_interior`，主角住宅室内**：第一章醒来、首次对白、基础操作提示与床铺睡觉，并为以后室内互动保留最小扩展空间。
2. **`hometown_main`，故乡日常主区域**：承载农场、住宅外部、主要村民活动和关系片段。当前 Demo 将农场与村庄合并在该地图，不再拆出第四张玩法地图。
3. **`boundary_pass`，结界边界区域**：承载通往故乡外部的道路、平静状态下的日常解释和第一处结界异常；玩家必须能够忽略调查并返回日常。

三张地图按“住宅门”和“北侧山路”串联，不提供住宅到边界的直接通道。当前 Demo 不增加额外玩法地图；以后若增加矿洞、秘境或独立村庄地图，必须经过新的范围决定。完整流程、平面草图和灰盒尺寸预算见 `docs/DEMO_MAP_FLOW.md`。

## Demo 体验支柱

### 1. 平静的农场生活

- 保留现有耕地、播种、浇水、睡觉、成长、收获、背包、快捷栏和存读档闭环。
- 至少提供雾叶草和一种辅助原创作物。
- 用正式地图、美术、音效、HUD 与操作反馈替换主要占位表现。
- 玩家完成基础引导后可以继续自由生活，而不是被强制推进到 Demo 结束。

### 2. 村庄与人物关系

- 阶段 10C 已固定 15 名 NPC：5 名幸存者与 10 名重构村民，名单和内部分类见 `docs/NPC_BIBLE.md`。
- 内容预算分为 4 名 `core`、5 名 `support` 和 6 名 `ambient`；所有人物都有明确身份、地图存在、原创对白和基础好感反馈，但不要求十五条完整个人线。
- 第一章是“主角重逢、玩家初识”。主角保留袭击前的关系记忆，新的好感和亲密仍由玩家在当前存档中建立。
- 完整产品预留男性/女性两种主角形态，并允许人物资料标记为可恋爱的当前无配偶 NPC 不分性别拥有适龄亲近表现。成年人可有双向轻微暧昧并按好感决定是否接受告白；未成年人只能有单方面稚嫩好感，主角不得浪漫回应，且 18 岁前告白必须拒绝。恋爱对象满好感后才可求婚；同一存档允许多条恋爱关系，但最多一名不限性别的配偶。
- 罗岑山、陈蕴等明确定位为老年长辈的角色只发展亲情、友情、信任、敬重与个人事件，不出现暧昧、告白、恋爱、求婚或婚姻内容。开场按好感判定告白的成年人是宁昭、晏巡、杜蘅、乔榆、沈禾、文澍、穆原、唐米、何舟、黎青和池雀；乔苓经过一个完整游戏年满 18 岁后才改用好感判定，阿桃未来成年时同理。当前不实现 NPC-NPC 恋爱。
- Demo 以沈禾承担恋爱可能性预览与首个立绘试制输入，以宁昭承担友谊/信任预览；宁昭在完整产品中仍是恋爱候选，两者都不在 Demo 中告白或锁定恋爱。第二套主角正式美术和角色创建界面不因本规则自动进入当前 Demo 范围。
- 完整 NPC 日程、告白/恋爱/求婚线、婚礼和婚后内容不作为本 Demo 的完成前提，任何关系选择也不能锁死第一处结界异常。

### 3. 第一处结界异常

- 异常发生前必须先建立足够可信的日常，让反差具有意义。
- 异常要让玩家确认村外存在无法正常穿越的结界，并留下可以继续调查的线索。
- 视觉和声音可以短暂从阳光风格转向阴冷、失真或不安，但之后允许玩家回到日常。
- Demo 不进入最终真相期，也不展示不可逆调查确认。

## Demo 内容下限

- 《雾乡如昨》标题界面与第一章开场。
- 新游戏、继续游戏、存档管理、最小设置和暂停。
- 至少三张经过正式表现、可独立加载且职责清楚的地图：住宅室内、故乡日常主区域、结界边界区域。
- 正式玩家角色、核心作物、基础环境、主要 UI 和关键反馈资源。
- 固定五名幸存者与十名重构村民的基础资料、地图存在、原创对白和基础好感状态。
- 至少一段沈禾恋爱可能性预览与一段宁昭友谊/信任预览，证明关系分支可存档且不阻塞调查入口。
- 第一处结界异常及其前后对白、视听变化和恢复逻辑。
- 最小音乐、环境声和耕种、对话、异常相关音效。
- 可读的日期、当前目标、快捷栏、互动提示、存档反馈与 Demo 阶段性结束提示。

正式美术不从完整村庄批量生产开始。第一批只制作一个玩家、一套草地/泥土、一栋小屋、一棵树和雾叶草完整成长阶段，并用同一小场景验证白天、黄昏、夜晚和下雨。详细规格与清单见 `docs/ART_BIBLE.md` 和 `docs/ART_ASSET_LIST.md`。

## 核心真相的保密边界

Demo 只让玩家得出“故乡边界不正常，而且部分人似乎知道原因”。以下内容不能在 Demo 中被直接证实：

- 军队袭击和大规模死亡；
- 神石实现的三个愿望；
- 第二愿望制造封闭结界；
- 第一愿望固定战争残响；
- 故乡是愿境；
- 重构村民是从死者记忆产生的新生命；
- 幸存者集体隐瞒的完整原因。

可以投放不会单独泄底的矛盾线索，但每条线索必须同时存在至少一种日常解释。

## 存档与不可逆真相线

### 当前实现

技术 MVP 目前只有一个自动存档槽，`Continue` 只能恢复这一份运行状态。现有保存结构也没有完整的 NPC、关系与叙事阶段数据。

### 推荐方案，尚待实现确认

- 提供三个彼此独立的玩家存档档位。
- “继续游戏”默认进入最近使用的档位，同时允许玩家进入存档界面改选。
- 每个档位继续使用自动保存，避免要求玩家频繁手动管理。
- 在最终真相期的不可逆调查确认前，为当前档位建立受保护的“调查前恢复点”。
- 恢复点不因进入真相期后的普通自动保存而覆盖；玩家可从存档界面明确回到该点。

仅增加三个档位不能替代恢复点，因为玩家可能已经使用全部档位，也不一定会主动复制存档。该方案需要 SaveData 版本迁移、档位元数据、叙事状态和 NPC 状态后再进入实现。

## Demo 不承诺完成

- 屠村、许愿和愿境形成的倒叙章；
- 最终真相期、最终 Boss 和完整结局；
- 通用 NPC 日程、十五人的完整个人好感事件、完整告白/恋爱/求婚线，以及婚礼/婚后内容；
- 完整矿洞、战斗、装备和怪物生态；
- 商店、货币与完整经济系统；
- 多人、节日、钓鱼和大型通用任务系统；
- 自研跨平台云存档；
- 超过三张基线且未经过范围确认的大量地图，以及完整商业版的多年内容。

矿洞、怪物或秘境可以在 Demo 中以小规模代表性片段出现，但必须先单独锁定范围；婚恋内容只执行本文件已确认的沈禾预览，不因完整产品允许多名角色拥有亲近内容而自动扩张。

## 完成门槛

Demo 只有同时满足以下条件才算达到公开试玩候选：

- 新玩家不靠开发者口头说明，可以从标题界面开始并理解基础农场循环。
- 玩家能记住至少数名村民，并理解游戏存在关系发展的空间。
- 玩家能发现第一处结界异常，知道调查是自己的选择。
- Demo 不意外泄露核心真相，也不自动进入不可逆阶段。
- 关键玩家可见画面不再依赖纯色几何占位资源。
- 标题、存档、HUD、对白、音频和异常反馈形成一致体验。
- 至少一次内部完整试玩与一次陌生玩家观察完成，关键阻塞问题有记录。
- 微信小游戏和 Windows 候选构建都能完成相同的 Demo 核心流程并安全保存。

## 详细设计仍待确认

- Demo 的目标游玩时长与内容节奏，以首轮纸面流程和试玩结果为准。
- 三张基线地图的最终尺寸与 NPC 精确坐标，以阶段 11 灰盒步行时间、摄像机和性能验证为准；职责、连接关系和初始预算已经锁定。
- 第一处结界异常的具体叙事节拍、线索内容和结束对白；阶段 10B 只锁定其功能结果与返回日常的规则。
- 十五名 NPC 的精确灰盒坐标与第一轮原创对白；名单、关系图、内容层级和关系预览人选已经锁定。
- 是否加入一段最小矿洞或战斗展示。
- 三档存档与调查前恢复点是否作为 Demo 必须项。
- Demo 的阶段性结束点，以及结束后能否继续自由生活。
