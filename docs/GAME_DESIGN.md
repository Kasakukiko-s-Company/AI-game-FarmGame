# 《雾乡如昨》游戏设计草案

本文描述“做什么游戏”，不作为最终技术实现、完整剧本或数值表。领域词汇以根目录 `CONTEXT.md` 为准，剧透设定以 `docs/NARRATIVE_BIBLE.md` 为准。

## 基本定位

- 名称：《雾乡如昨》
- 类型：原创 2D 像素风农场生活模拟、角色关系与可选悬疑微恐探索
- 视角：俯视角
- 目标平台：微信小游戏与 Steam Windows；共享玩法保持一致，平台能力通过 adapter 隔离
- 画面方向：横屏，640×360 逻辑设计分辨率
- 推进方式：按游戏日推进，允许长期自由生活；真相线由玩家主动调查推进
- 目标玩家：喜欢种田、村民关系、恋爱、东方幻想，以及愿意主动探索隐藏世界真相的玩家

## 核心体验承诺

游戏在正常情况下是一款可以长期游玩的温暖农场生活模拟：玩家耕种、交友、发展感情，偶尔外出探索秘境、挖矿和战斗。

与同类游戏的主要区分不是把恐怖事件强加给所有玩家，而是提供一条隐藏但真实存在的真相线：

- 不追查异常时，玩家可以长期停留在平静或轻微渗漏阶段。
- 主动调查后，阳光日常逐渐转为阴暗、压迫和微恐，出现更强的怪物与战争残响。
- 进入最终真相期前必须有清晰、可理解的不可逆确认与恢复保障。
- 平静日常和真相线不是两个互相否定的游戏；玩家建立的关系正是真相产生伦理重量的原因。

## 核心循环

完整产品的候选日常循环：

> 规划一天 → 种植与照料 → 与村民相处 → 探索或处理个人目标 → 收获与整理 → 睡觉结算 → 新的关系和世界变化

完整产品的候选真相循环：

> 发现异常 → 选择是否追查 → 收集互相矛盾的线索 → 面对幸存者的隐瞒 → 确认不可逆调查 → 处理战争残响与愿境未来

已经完成的技术 MVP 只验证：

> 移动 → 锄地 → 播种 → 浇水 → 睡觉 → 成长 → 收获 → 保存与恢复

当前 Demo 要在该闭环上证明：

> 第一章醒来 → 建立一段可信日常 → 认识数名村民 → 完成代表性关系互动 → 发现第一处结界异常 → 选择以后调查或继续生活

详细边界和验收标准见 `docs/DEMO_SCOPE.md`。

## 世界与地图

- 世界是处于多国乱战中的架空魔法世界。
- 主角原本是魔法学院新生；学院卷入战争后无限期封校，待局势稳定再决定是否复办。
- 故乡被山雾环绕，表面上仍保有农场、住民和日常秩序。
- 完整产品候选区域包括农场、村庄、山麓、溪谷、矿洞和秘境；Demo 只实现形成代表性体验所需的受控区域。
- Demo 使用三张可独立加载的玩法地图：`home_interior` 承担住宅醒来和床铺跨天，`hometown_main` 合并农场与村庄并承担长期生活，`boundary_pass` 承担第一处结界异常。标题、档位和设置属于应用 UI，不计入地图数量。
- 住宅通过房门连接日常主区域，日常主区域通过北侧山路连接边界；住宅与边界没有直达入口。当前 Demo 不增加第四张玩法地图。
- 初始灰盒预算分别为 `20×12`、`64×48` 和 `40×24` 个 `32×32` 瓦片。阶段 11 可以依据步行时间、摄像机和移动端性能按 4 格倍数微调，但不得改变职责与连接。
- 当前 30×30 药圃只是技术 MVP 原型。阶段 11 先按 `docs/DEMO_MAP_FLOW.md` 完成灰盒和场景切换，阶段 16 才替换为正式地图表现；不得直接把原型扩成完整世界。

## 时间、耕种与成长

- 游戏按天结算作物成长，玩家主动睡觉结束当天。
- 当天浇水的作物成长；未浇水只停长，不枯死或倒退。
- Demo 至少保留雾叶草并增加一种辅助原创作物，以验证 JSON 驱动的内容扩展。
- 体力、天气、季节、商店、价格、加工与经济循环需要另行设计，不因完整愿景自动进入当前范围。

## 村民与关系

- 当前 Demo 固定 15 名 NPC：五名真实幸存者和十名重构村民；完整名单见 `docs/NPC_BIBLE.md`。
- 重构村民是由死者记忆原型生成、会产生新记忆与选择的新生命，不是复活者或空壳。
- 内容分为 4 名核心、5 名支撑和 6 名氛围角色；15 人全部拥有可升可降的好感记录，内容层级只控制基础对白、专属事件和立绘深度。
- 主角记得袭击前的村民，第一章是重逢而非陌生人初见；既有关系记忆不自动授予当前存档好感。
- 完整产品预留男性/女性两种主角形态。年龄随世界日期增长，只有人物资料标记为允许恋爱的当前无配偶 NPC 可以拥有适龄亲近表现；主角形态和 NPC 性别都不限制恋爱资格。成年人可有轻微暧昧；未成年人只能有不被主角浪漫回应的稚嫩好感，且 18 岁前告白必定拒绝。成年人是否接受告白由当前好感决定。
- 罗岑山、陈蕴等明确定位为老年长辈的角色只发展亲情、友情、信任、敬重与个人事件，不出现暧昧、告白、恋爱、求婚或婚姻内容；这是一项稳定的人物内容边界，不以动态年龄数值自动切换或解除已有关系。
- 同一存档允许多名合资格成年 NPC 在接受告白后同时处于恋爱关系，但结婚只能选择一名不限性别的配偶。恋爱对象满好感后才可求婚；好感、亲近表现、恋爱和唯一配偶必须分别建模。
- 当前不模拟 NPC-NPC 恋爱，他们之间只使用友情、信任、竞争和厌恶等非恋爱关系。
- Demo 只以沈禾验证成年亲近/恋爱可能性，以宁昭验证友谊/信任，并为全员提供基础好感反馈；宁昭的完整产品恋爱资格不因此关闭。完整告白、恋爱、求婚、婚礼、婚后内容和第二套主角正式美术不作为 Demo 完成前提。

## 探索与战斗

- 挖矿、秘境和战斗属于完整游戏愿景，用于改变日常节奏并承载战争残响与世界真相。
- 战争残响不是军队死者的灵魂，而是第一愿望固定在现世的诅咒性存在。
- Demo 是否加入一个最小探索或战斗片段尚未确认；未确认前不得建设完整矿洞、装备或怪物系统。

## 叙事结构

- 游戏直接从第一章开始：主角在记忆封印后于家中醒来。
- 学院生活、初次回乡、原本日常、秘境、神石、军队袭击与三个愿望属于后续倒叙章，而不是序章。
- Demo 只展示第一处结界异常，不揭露屠村、愿望、愿境或重构村民来源。
- 玩家不调查时可以长期生活；普通日数、种田进度和恋爱进度不会自动触发最终真相期。
- 主角最终成长主题是“保护不等于控制”：承认自己的愿望造成封闭，尊重重构村民作为新生命的选择，并从保存昨日转向共同面对未来。

## 操作与平台

- PC：WASD/方向键移动，快捷键或按钮选择工具，交互键执行动作。
- 微信：横屏双手操作，左侧虚拟摇杆，右侧独立动作按钮，快捷栏位于不遮挡主要视野的位置。
- 两端共享同一组语义输入，不让玩法依赖具体按键。
- Steam 是 Windows 原生运行环境的发行渠道，不把 Steam SDK 混入共享玩法。

## 美术与声音

- 正式方向为“原创 HD 像素增强版”：首版 96×96 角色、32×32 Tile、高清像素环境、轻量光照、粒子氛围和少量共享 Shader。
- 游戏保持纯 2D/轻量 2.5D 表现，不采用完整 3D HD-2D 场景。
- 表层日常使用温暖、通透的视觉；渗漏和真相线通过光照、色板、环境层、音频与少量关键替换资源逐步变暗。
- 双状态不等于复制两套全部美术，优先共享基础资源并建立可控的氛围切换管线。
- 微信默认低画质与 PC 默认高画质只改变表现开关和预算；所有增强效果都能关闭，不影响核心玩法。
- 字体、音乐、音效和图像均须原创或有明确许可证记录。

详细规格见 `docs/ART_BIBLE.md`；首批只制作 `docs/ART_ASSET_LIST.md` 中的五类视觉验证资源，不直接批量生产完整游戏美术。

## 存档原则

- 技术 MVP 当前实现一个自动存档槽。
- 为支持多角色档案和不可逆真相线，推荐升级为三个独立档位，“继续游戏”默认最近使用档位。
- 不可逆调查前还需要同档位内受保护的调查前恢复点；三个普通档位本身不能替代恢复保障。
- 该方案需要 SaveData 版本迁移、NPC/关系/叙事状态后再实现，当前未落地。

## 当前 Demo 边界

当前只承诺 `docs/DEMO_SCOPE.md` 中的代表性体验。全员关系状态属于 Demo 架构基线，但完整告白/恋爱/求婚事件、婚礼/婚后内容、通用 NPC 日程、矿洞、战斗、商店、经济、超过三张基线的大量地图、倒叙真相章和结局均需要后续单独确认范围。
